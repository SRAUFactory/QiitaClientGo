# git-release-tag

タグのpushでGitHub Actionsのリリースワークフロー(`on: push: tags: 'v*'`)を起動するリポジトリ向けに、リリースタグを安全に作成するための手順。

## 前提

- タグはpushした時点でリリースが走る。作成前に必ず確認を取り、確認なしにpushしない。
- ワークフローは「タグが指すコミット」のものが使われる。ワークフローを修正した場合は、修正を含むコミットにタグを付ける。
- 失敗した実行の「Re-run」は同じコミットで動くため、ワークフローの不具合は直らない。

## 手順(新規タグ)

1. **タグ名を決める**
   - `vMAJOR.MINOR.PATCH` 形式(例: `v1.0.1`)であることを確認する。
   - 指定がなければ `git tag --sort=-v:refname | head` で直近のタグを見て、次のバージョンをユーザーに提案する。

2. **事前チェック(すべてコマンドで確認する)**
   - `git status --porcelain` が空であること(未コミットの変更がない)。
   - `git branch --show-current` がリリース元のブランチ(通常は `master` か `main`)であること。
   - `git fetch origin` のあと、`git rev-parse HEAD` と `git rev-parse origin/<branch>` が一致すること(未pushのコミットがない)。
   - `git tag -l <tag>` と `git ls-remote --tags origin <tag>` の両方で、同名タグが存在しないこと。
   - `.github/workflows/` にリリース用ワークフローがあれば内容を読み、タグ名の変数が正しく渡されているか確認する。

3. **ユーザーに確認する**
   - 「タグ名」「付与先のコミット(`git log -1 --oneline`)」「pushするとリリースが走ること」を伝え、実行してよいか確認する。

4. **作成してpushする**

   ```bash
   git tag -a <tag> -m "Release <tag>"
   git push origin <tag>
   ```

   注釈付きタグ(`-a`)を使う。軽量タグは使わない。

5. **検証する**
   - `git ls-remote --tags origin <tag>` で、タグ本体の行と `^{}` の行(指すコミット)の両方が出ること。
   - `^{}` のコミットが、想定したコミットと一致すること。
   - GitHub Actionsの実行が始まったか、実行ページで確認するようユーザーに案内する(ログの閲覧にはサインインが必要な場合がある)。

## 手順(タグの付け直し)

既存タグを削除して再作成する操作は破壊的である。リモートのタグを削除するため、**必ずユーザーの明示的な承認を得てから**行う。

1. 既存タグの状態を確認する。
   - `git rev-parse <tag>^{commit}` と `git ls-remote --tags origin <tag>` で、現在どのコミットを指しているか確認する。
   - そのタグで作られたGitHub Releaseが残っていないか、ユーザーに確認する(残っていれば先にReleasesページで削除してもらう)。
2. 修正を含むコミットがpush済みであることを、手順(新規タグ)の事前チェックで確認する。
3. 承認を得たうえで、次を順に実行する。
   ```bash
   git tag -d <tag>
   git push --delete origin <tag>
   git tag -a <tag> -m "Release <tag>"
   git push origin <tag>
   ```
4. 手順(新規タグ)の「検証する」を行う。

## 禁止事項

- ユーザーの承認なしに、タグのpush、削除、付け直しをしない。
- `git push --force` は使わない。
- 未コミットの変更や未pushのコミットがある状態で、タグを付けない。
- 他のブランチや過去のコミットへ付ける場合は、ハッシュを明示してユーザーに確認する(`git tag -a <tag> <hash> -m "..."`)。

## 報告

完了したら、タグ名、指すコミットのハッシュ、検証結果(`ls-remote` の出力)を簡潔に伝える。うまくいかなかった場合は、失敗したコマンドとエラーをそのまま示す。
